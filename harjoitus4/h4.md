## x) lue ja tiivistä
* **4.12.1Size and Complexity of Some DSLs:** Konfiguraatiokielen laajuus vaihtelee hyvin suppeasta aina ohjelmointikielimäiseen. *Oma huomio: Yksinkertaisuus vähentää virheitä, kun taas laaja kieli auttaa monimutkaisissa ympäristöissä.*
* **4.12.2 Use of DSL Functions in Case Configuration:** Vain pientä osaa ominaisuuksista käytetään todellisuudessa. Työ painottuu täysin perustoimintoihin, kuten asennuksiin. *Oma huomio: Tämä perustelee hyvin yksinkertaisen package-file-service -mallin tehokkuuden.*
* **4.12.3.1 Dependencies Between Main Functions:** Funktioiden väliset riippuvuudet (esim. asetusten muutos vaatii palvelun uudelleenkäynnistyksen) ovat hallinnan keskiössä. *Oma huomio: Ansiblen Handlerit hoitavat tämän estäen turhat uudelleenkäynnistykset.*

## a) Rapyla
Valitsin demoniksi postgresql:n, en oikein syytä keksi miksi juuri tämän enkä ole ikinä tästä kuullut enkä tiedä miten tämä toimii, varmaakin kun käyn samalla SQL-kurssia niin herätti mielenkiinnon. Valinnan jälkeen asensin tämän apt-pakettienhallinnasta ja tarkistin asennuksen onnistumisen palvelun tilasta.

```bash
sudo apt update
sudo apt install postgresql 
systemctl status postgresql
```

## d) Paikka remonttiin
Sitten rikoin pienesti tätä poistamalla asetustiedoston kokonaan käsin ja yritin komennolla `sudo systemctl restart postgresql` saada virheilmoitusta, mutta se ei tulostanut mitään, sain haluamani todisteen sitten komennolla `sudo systemctl status postgresql@17-main`.

<img width="643" height="47" alt="image" src="https://github.com/user-attachments/assets/f2029e67-e310-4946-b686-17ca02d7b2ce" />

<img width="643" height="216" alt="image" src="https://github.com/user-attachments/assets/eee59e14-ff0a-46bb-bb84-f947d0d8ddfb" />

Sitten yritin korjata tilanteen pakettienhallinnan avulla (`sudo apt-get install postgresql`). Tässä ei oikein minulla ajatus toiminut koska olin unohtanut että en ollut poistanut koko demonia, pelkästään tuon asetustiedoston, joten tästä ei ollut mitään hyötyä.

<img width="643" height="182" alt="image" src="https://github.com/user-attachments/assets/2a9e1ba8-559b-43df-8ec8-2ffaca6f2be0" />

Turvauduin tässä sitten tekoälyn apuun koska en vain saanut päähäni ratkaisua, sen avulla ajoin Ansible-playbookin, joka palauttikin poistetun konfiguraation ja käynnisti demonin handlerilla. Tarkistin tilan nyt uudelleen, ja nyt palvelu oli taas toiminnassa.
