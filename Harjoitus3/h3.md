## x) Lue ja tiivistä

### Karvinen 2026: Apache installed with Ansible - quick notes
* **Package-file-service -malli:** Demonit, kuten apache2, asennetaan ja konfiguroidaan eri vaiheissa: asennetaan paketti, muokataan asetustiedostoja  ja käynnistetään uudelleen.
*  **Handlerit:** Tiedostojen muutokset tulevat voimaan vasta, kun demoni käynnistetään uudelleen. Siksi tehtävissä käytetään `notify: restart apache2` -kutsua, joka käynnistää `handlers/main.yml` -tiedostossa uudelleenkäynnistyksen.
*  **Oma huomio:** Kun konfiguraatio linkitetään linkillä `sites-available`-kansiosta `sites-enabled`-kansioon, sivu on helppo ottaa pois käytöstä poistamalla pelkkä linkki ilman, että alkuperäinen tiedosto katoaa.

### Ansible Community Documentation: Handlers: running operations on change
* **Handlers johdantokappale:** Handlerit ovat tehtäviä, jotka suoritetaan vain silloin, kun jokin tehtävä tekee muutoksen kohdekoneelle ja lähettää handerille ilmoituksen. Esimerkiksi palvelu käynnistetään uudelleen vain, jos sen asetustiedosto oikeasti muuttui.
* **Notifying handlers:** Tehtävä voi kutsua useampaa handleria `notify` -avaimella. Handlerit suoritetaan siinä järjestyksessä, miten ne on määritelty `handlers` -osiossa.
* **Oma huomio:** Tuntuu fiksulta, että Ansible ajaa handlerin vain kerran kaikkien tehtävien päätteeksi, ettei palvelin käynnisty uudelleen turhaan jokaisen pienen muutoksen välissä.

* ### `ansible-doc service`
* **Johdanto:** Hallinnoi ja ohjaa taustapalveluita (daemons/services) etäkoneilla.
* **Optiot:**
  * `enabled`: Määrittää, käynnistyykö palvelu automaattisesti koneen käynnistyessä.
  * `name`: Hallittavan palvelun nimi (pakollinen asetus, esim. `apache2`).
  * `state`: Palvelun haluttu tila: `started` (käynnissä), `stopped` (pysäytetty), `restarted` (käynnistetään uudelleen) tai `reloaded` (ladataan asetukset uudelleen).
* **Esimerkki:**

```yaml
- name: Start service httpd, if not started
  ansible.builtin.service:
    name: httpd
    state: started
```

## a) Apassi

Ekana asennettiin Apache2 -webbipalvelin käsin:

```bash
sudo apt-get update
sudo apt-get install -y apache2
```

Loin käyttäjänä kotihakemistooni `publicsite` -kansion ja sinne `index.html` -etusivun.

```bash
mkdir /home/tommik/publicsite
````

Webbipalvelin toimii käyttäjänä `www-data`, siksi annoin kansioihin kulkuoikeuden (`x`) ja tiedostoon lukuoikeuden (`r`):

````bash
chmod ugo+x /home/tommik/
chmod ugo+x /home/tommik/publicsite/
chmod ugo+r /home/tommik/publicsite/index.html
````

Seuraavaksi loin Apachelle uuden VirtualHost-asetustiedoston komennolla `sudoedit /etc/apache2/sites-available/example.con.conf` :

```apache
# Managed file, changes will be overwritten

<VirtualHost *:80>
        ServerName example.com
        DocumentRoot /home/tommik/publicsite/

        <Directory /home/tommik/publicsite/>
                require all granted
        </Directory>
</VirtualHost>
```

Tekoälyn ohjeiden avustuksella poistin Apachen oletussivun linkin käytöstä, linkitin oman sivuni `sites-enabled` -kansioon, tarkistin ja käynnistin Apachen uudelleen:

```bash
sudo rm -f /etc/apache2/sites-enabled/000-default.conf
sudo apache2ctl configtest
sudo systemctl restart apache2
curl http://localhost
```

## b) Moottorix

Sammutin ekana Apachen, jotta portti 80 vapautui Nginxille ja sitten asensin Nginx-webbipalvelimen:

````bash
sudo systemctl stop apache2
sudo systemctl disable apache2
sudo apt-get install -y nginx
````

Tehtävän ohjeiden mukaisesti katsoin `/etc/nginx/sites-available/default`-tiedoston loppua ja loin uuden asetustiedoston komennolla `sudoedit /etx/nginx/sites-available/example.com.conf` :

```nginx
server {
        listen 80;
        listen [::]:80;

        server_name example.com;

        root /home/tommik/publicsite;
        index index.html;

        location / {
                try_files $uri $uri/ =404;
        }
}
```

Tekoälyn ohjeiden avustuksella poistin Nginxin oletussivun, testasin syntaksin ja käynnistin Nginxin uudelleen:

```bash
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl restart nginx
```

Päivitin `index.html` -tiedoston käyttäjänä ilman sudoa ja testasin sivun:

```bash
echo '<h1>Tommin Moottorix (Nginx) toimii!</h1>' > /home/tommik/publicsite/index.html
curl http://localhost
```

## c) Automoottorix

Loin uuden kansion `~/h3` ja tein sille Ansible roolirakentaan (`roles/nginx/`), kopioin tekoälyn ohjeilla `ansible.cfg` - ja `hosts.ini` -tiedostot edelliestä harjoituksesta sekä kopioin b-kohdassa tehdyn toimivan Nginx-konfiguraation:

```bash
mkdir -p ~/h3/roles/nginx/files ~/h3/roles/nginx/handlers ~/h3/roles/nginx/tasks
cp ~/h2/ansible.cfg ~/h2/hosts.ini ~/h3/
cd ~/h3
cp /etc/nginx/sites-available/example.com.conf roles/nginx/files/example.com.conf
```

**`roles/nginx/handlers/main.yml`:**

```yaml
- name: restart nginx
  systemd:
    name: nginx
    state: restarted
```

**`roles/nginx/tasks/main.yml`:**

```yaml
- apt:
    name: nginx
    state: present
    update_cache: true

- copy:
    dest: "/etc/nginx/sites-available/example.com.conf"
    src: "example.com.conf"
    owner: "root"
    group: "root"
    mode: "0644"
  notify: restart nginx

- file:
    src: /etc/nginx/sites-available/example.com.conf
    dest: /etc/nginx/sites-enabled/example.com.conf
    owner: root
    group: root
    state: link
  notify: restart nginx

- file:
    dest: /etc/nginx/sites-enabled/default
    state: absent
  notify: restart nginx
```

**`site.yaml`:**

```yaml
- hosts: all
  become: true
  roles:
    - nginx
```

Automaation toimivuutta testasin poistamalla ensin luodun symbolisen linkin `/etc/nginx/sites-enabled/example.com.conf` ja tämän jälkeen ajamalla playbookin:

```bash
sudo rm -f /etc/nginx/sites-enabled/example.com.conf
ansible-playbook site.yaml
curl http://localhost
```

Ansible huomasi tuon puuttuvan linkin, loi sen uudelleen ja näytti sen `changed` -kohdassa ja kutsui ajon lopuksi handleria, joka käynnisti Nginxin uudellen. Lopuksi `curl http://localhost` tulosteessa näkyi taas oma kotisivuni.
